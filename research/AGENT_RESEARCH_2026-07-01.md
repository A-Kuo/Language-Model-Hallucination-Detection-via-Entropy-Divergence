## Summary
The field has moved decisively past raw predictive/token entropy and even past first-generation semantic entropy: 2025–2026 work concentrates on (1) cheaper, sample-efficient estimators of semantic entropy via Bayesian/adaptive sampling, (2) richer similarity/clustering structure for the entropy calculation itself (kernel, nearest-neighbor, Gaussian-process variants), and (3) production-grade wrapper frameworks (UQLM, vLLM's HaluGate) that turn any of these scores into a standardized, latency-cheap confidence signal. For Austin's repo, this validates the entropy-divergence approach directionally but suggests the current implementation is likely still on "v1" naive entropy — there is a clear, well-documented upgrade path to Bayesian-estimated semantic entropy that cuts required samples by ~50% for the same detection quality.

## Engineering Insights
- Zero-resource, wrap-the-LLM frameworks (e.g., UQLM) standardize black-box, white-box, and judge-based scores into a single 0–1 confidence number — this is the pattern to imitate for a clean public API (`score = detector.score(prompt, response)`), rather than exposing raw entropy/divergence values.
- Production guidance from the vLLM HaluGate writeup: detection overhead of 76–162ms is negligible next to 5–30s generation latency, so token/sequence-level entropy scoring is cheap enough to run inline on every request rather than being sampled — but the current repo should still expose a `sample_rate` or `min_confidence` gate to skip low-risk content (e.g., creative writing) and avoid false positives.
- Multiple 2025–2026 sources recommend reporting per-failure-mode rates instead of one aggregate hallucination number (six recognized failure modes referenced in recent survey coverage) — worth adding a breakdown (e.g., factual-error vs. unsupported-claim vs. self-contradiction) to the repo's evaluation output rather than a single scalar.
- Bayesian/adaptive sampling (spend more samples only on genuinely ambiguous generations) is now the standard efficiency trick for semantic-entropy-style detectors — a fixed sample count (e.g., always N=10) is measurably wasteful compared to an adaptive scheme.
- For RAG-adjacent use cases, faithfulness/groundedness scoring (claim extraction → verify against context → proportion supported) is treated as a separate, higher-priority metric from generic entropy-based hallucination detection — if this repo is ever pointed at RAG outputs, that should be a distinct scoring path, not conflated with the entropy score.

## Recommended Next Actions
1. Add an adaptive/Bayesian sampling option to the entropy estimator (start with a simple two-stage scheme: cheap low-N estimate first, escalate to higher N only when the low-N estimate is near the decision threshold) — directly modeled on the ~50%-fewer-samples result from the Adaptive Bayesian Estimation paper.
2. Add a kernel- or nearest-neighbor-similarity option for the semantic clustering step (alternative to hard clustering) so entropy scores are smoother/less sensitive to cluster-boundary noise, referencing Kernel Language Entropy.
3. Add per-failure-mode breakdown to the evaluation output (JSON/CSV with categories, not just a single scalar divergence score) so results are comparable to current published benchmarks that report multi-mode rates.
